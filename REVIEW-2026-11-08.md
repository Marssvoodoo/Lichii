## Remaining focused experiment

NVIDIA and AMD proprietary drivers normally bypass Lichii's explicit Vulkan
pipeline cache because the project found their own caches sufficient and wanted
to avoid redundant memory/copy costs. This is intentional policy, not a confirmed
bug. `485af70` adds `EDEN_NX2_FORCE_DRIVER_CACHE=1` to compare the existing explicit
cache path per launch; its default behavior is unchanged.

The opt-in build starts successfully, reuses the preparation, and writes an
approximately 148 MB explicit cache. This proves the path works, not that it is
faster. Same-build OFF/ON/reload and fresh-view comparisons remain required before
claiming an improvement or recommending it as a permanent setting. No global
NVIDIA setting or external driver cache was changed or cleared.

## Scope and coverage

The initial tracked map contains 3,590 source/build files and 707,609 application
and build lines, with vendored implementations counted separately. clang-tidy
22.1.3 analyzed 1,459 active C/C++ translation units from the actual Windows compile
database. Two resource scripts were rejected by clang-tidy's C++ driver and are
covered by the successful resource-compiler application build. Two new test units
bring the final active C/C++ coverage to 1,461; changed paths were rechecked in
separate analysis runs with no compiler errors or timeouts.

Manual review traced critical shader/IR/SPIR-V generation, prepared-cache formats
and validation/fallbacks, driver creation and draw waits, worker capture lifetimes,
pipeline retention, descriptor/buffer/texture/query/fence ownership, DLSS result
handling, CPU CLZ and timing, NUP parsing/decompression, file-service boundaries,
save/VFS/update operations, loopback debug service, configuration inheritance,
input/audio and network entry points, plus dependency/build selection.

This is a whole-project inventory and automated scan with manual review of
critical paths, not a claim that every line or all 1200-plus core-service files
were read manually. Vendored Dynarmic/third-party internals and inactive platforms
were not exhaustively audited or fuzzed; dependencies were inventoried rather
than subjected to a comprehensive CVE or license audit.

The scan emitted 1,001 diagnostic instances, 136 distinct diagnostic lines across
application, test and dependency headers. They are candidates, not 136 bugs.
Examples checked against actual code: parent/member offset array sizing is
intentional; SlotVector destroys moved-from objects correctly; image-download
retention moves the image once then shares it; SSL handshake EOF guards precede
the nullable size parameter; kernel allocation checks its nonzero allocation;
memory-state output values are initialized on successful calls; ASTC mode guards
bound its weight-table index. Lambda-capture and count-leading-zero analyzer
modeling also produces warnings contradicted by the initialized captures and
nonzero guards. Unconfirmed diagnostics remain recorded for deeper fuzzing and
caller analysis, without being promoted to verified vulnerabilities.

## NX2navi comparison

[NX2navi 0.5.0](https://github.com/tangerineturtle1/NX2navi/releases/tag/v0.5.0)
is a native Windows recompilation for game 1.1.1. Its pinned
[architecture](https://github.com/tangerineturtle1/NX2navi/blob/v0.5.0/docs/architecture.md)
uses ahead-of-time shader-stage libraries and fast pipeline linking, making it a
relevant separate comparison for this symptom. The release still lists roughly
0.2-second area setup stalls, first-visit driver builds and a rare particle crash.
It requires an initial 10-25-minute local build. No claim of superiority on this
PC is made without testing; it has not been installed in this review.
